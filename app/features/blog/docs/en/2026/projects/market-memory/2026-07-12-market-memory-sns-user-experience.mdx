## It Started With a Single Question

As I began opening up Market Memory little by little, I naturally started thinking about how to run its SNS presence too.

The first thing I thought about was how to operate the accounts.

The service supports Korean, Japanese, and English.

So the question was: is it better to post in alternating languages from a single account, or to split the accounts by language?

At first, a single account looked like the better choice.

Followers gather in one place, and posts accumulate in one place.

The account's activity history stays concentrated, and the brand stays unified.

For a service that is just getting started, it seemed like an attractive enough option.

## But I Was Missing One Thing

When I thought about it more, I realized that I read Korean, I read Japanese, and English isn't much of a problem for me either.

So even when I looked at a feed with mixed languages, it didn't particularly bother me.

But most users aren't like that.

A Korean user expects Korean posts,

a Japanese user expects Japanese posts,

and an English user expects English posts.

For example, imagine a Korean user follows the account and the feed flows like this:

* Monday: English
* Tuesday: Japanese
* Wednesday: English
* Thursday: Korean
* Friday: English

The user might end up reading only one of the five posts.

To me it is a "multilingual account,"

but to the user it becomes "an account that often posts things I can't read."

That was the moment it hit me.

The structure that is convenient for me and the structure that is convenient for the user may not be the same.

## I Was Only Thinking From the Operator's Point of View

Looking back, the reason was simple.

It was because I wasn't the one being inconvenienced.

So I naturally assumed the users would be fine too.

It was less a thought and more a misunderstanding.

I hadn't really considered what kind of experience someone encountering this account for the first time would have.

When building the service, I always tried to think from the user's perspective first,

but on SNS, I had somehow started looking at the operator's convenience first.

## The Direction Market Memory Pursues Was the Same

In fact, the reason I'm building Market Memory is similar.

News already floods the world.

What I want to build is not a service that shows more news,

but a service that organizes the flow of the market so users can understand it more easily.

This SNS question, in the end, came back to the same one.

Not "Is this easy to operate?"

but,

"Is this easy for users to consume?"

That single question started to change the direction.

## The Direction Ahead

I don't intend to declare a definitive answer right away.

I plan to actually run things, look at the data, and check how users respond.

But as of now, rather than a single multilingual account, I'm leaning toward the idea that

**a single service running official channels in several languages** feels more natural.

Because rather than gathering an account's followers in one place,

giving each user an experience where they can naturally read the entire feed might be more important.

## The Current State of Operation and Results

After settling on this direction, I immediately added two sub-accounts.

Right now I've started posting in each language across three Threads accounts split into English, Korean, and Japanese.

The accounts were only created recently and don't get much exposure yet, so the posts aren't spreading at any meaningful scale.

Since starting SNS posting, visitors to the Market Memory homepage have increased slightly compared to before,
but there are still no new sign-ups. So far it hasn't reached a stage where there are clear results worth calling an achievement.

Still, this is something that has only just begun.

Rather than judging the direction based on immediate numbers, I want to keep up regular posting for now.
I plan to gradually change the format of the content, the posting times, the topics, and the way things are expressed,
and see which approaches are received more naturally in each language region.

For now, experiments and records matter more than results.

## One Small Realization

This reflection meant more than just deciding on a single SNS operating strategy.

When building a product, at some point the operator in me can start to come before the user.

This time, fortunately, I noticed that early on.

Going forward, whenever I build a new feature or service, I want to occasionally ask myself the same question.

**"Is this choice really for the user, or is it just for my own convenience?"**

For now, simply remembering this one question was harvest enough.
