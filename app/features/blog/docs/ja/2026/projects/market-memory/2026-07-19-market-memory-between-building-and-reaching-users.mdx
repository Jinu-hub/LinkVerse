## フェーズ1のあとに見えた現実

Market Memoryのベータ版を公開し、  
フェーズ1で実装しようとしていた機能も、おおよそ揃った。

モバイル最適化や細かい調整はまだ残っているが、  
少なくともサービスを外に見せて、ユーザーを受け入れられる段階には来たと思っていた。

だから次に始めたのが、マーケティングだった。

開発に比べると慣れていないし、得意だとも言いにくい領域だ。  
最初から大きく始めるよりは、自分で続けられる範囲で落ち着いて進めたかった。

最初に選んだチャネルは Threads だった。

英語、日本語、韓国語のユーザーが一つのアカウントに混ざるより、  
言語ごとに分けたアカウントのほうがいいと判断して、3つのサブアカウントを作った。

それぞれのアカウントでは、その言語でデイリーのマーケットメモリを投稿している。  
個別レポートが生成されたときも、内容を短くまとめて投稿している。

平日には、アカウントごとに1日5〜6件の投稿になることもある。

そうして運用を始めてから、1週間を超えた。

結果は正直に言って、よくない。

反応はほとんどなく、  
Threads 経由で Market Memory に登録したユーザーは、まだ一人もいない。

## 作ることと知らせることは別の問題だった

今回いちばん痛感したのは、  
何かを作る力と、それを人に知らせる力はまったく別だということだ。

自分は開発者として、必要な機能を考え、  
構造を設計し、  
実際に動くものを作る作業には慣れている。

問題があれば原因を見つけて直せる。  
足りない機能があれば足せる。  
画面が使いにくければ改善できる。

でもマーケティングは少し違った。

時間をかけて投稿を作り、継続して出しても、  
まったく反応が返ってこないことがある。

どこが間違っているのかも、すぐにはわかりにくい。

投稿の内容が問題なのか、  
アカウントに信頼がないからなのか、  
サービスの説明が足りないのか、  
Threads というチャネルが合っていないのかすら、はっきりしない。

1週間という期間だけでサービス自体を判断するには、まだ早い。

かといって、今と同じやり方で投稿だけを増やせば、  
いつか結果が変わると確信できるわけでもない。

ここまで作ってきたものは、  
よいコンテンツを複数言語で配信できるパイプラインに近い。

だが、コンテンツを出すことと、  
人がそれを見つけ、関心を持ち、サービスを使い始めるようにすることは、  
別の問題だった。

## 最初から流入をもっと考えるべきだったのか

こういう状況になると、  
最初の企画段階から、人を呼び込む方法をもっと考えておくべきだったのではないか、という思いも出てくる。

Market Memory を作りながら、  
レポート生成の構造や多言語対応、アーカイブ、ダッシュボード、自動化には多くの時間を使った。

一方で、ユーザーがこのサービスをどこで最初に見つけるのか、  
何を見て関心を持つのか、  
そしてどんな理由で登録するのかは、  
比較的あとから本格的に考え始めた。

だからといって、ここまでの開発が間違っていたとは思っていない。

Market Memory は実際に動いていて、  
自分が作りたかった分析の構造もある程度は実装されている。

ただ、プロダクトのフェーズ1は終わっても、  
ユーザーにプロダクトを届ける過程は、いま始まったばかりに近い。

プロダクト開発はフェーズ1まで来たが、  
ユーザー獲得とマーケティングは、まだフェーズ0なのかもしれない。

## 止まってしまった次の段階

もともとの計画では、今ごろは少数でもユーザーが登録し始め、  
その使い方とフィードバックをもとにサービスを改善していきたいと思っていた。

そのなかでフェーズ2の機能を具体化し、  
これからのロードマップも少しずつ整理するつもりだった。

でも今は、その流れが作れていない。

ユーザーがいなければ、実際の利用のなかで何が不便かもわからない。

人々がどんな機能を求めているかもわからない。

自分が大切だと思った機能が、ユーザーにとっても大切かどうか確かめる方法もない。

その状態でまた機能を足し始めると、  
結局、自分が必要だと思うものを一人で作り続けることになりやすい。

だから今は、以前考えていたフェーズ2をそのまま始めるのは難しい。

かといって、プロジェクトを止めたいわけではない。

むしろ、フェーズ2の意味をしばらく変えたほうがいいかもしれない。

機能を広げる段階ではなく、  
Market Memory が誰にどんな価値を与えられるのかを、直接確かめる段階として、という意味だ。

## 登録者より先に確認すべきこと

最初は、登録者が増えないとフィードバックも得られないと思っていた。

でも、誰も自然には入ってこないなら、  
待っているだけでは何も確認できない。

まず少数の人に直接見せて、反応を聞く必要がある。

登録したかどうかを聞く前に、  
もう少し基本的な問いから確認する必要がある。

Market Memory が何をするサービスなのか、初めて見る人にもわかるか。

サンプルレポートを見て、もっと読みたいと思うか。

既存のニュースや投資コミュニティ、証券アプリと比べて、また訪れる理由があるか。

そして、アカウントを作るほどはっきりした価値があるか。

今は登録者数十人よりも、  
こういう問いに正直に答えてくれる数人のユーザーのほうが必要かもしれない。

## Threads だけを見ないことにした

Threads をすぐに諦めるつもりはない。

まだ運用期間は短く、アカウントに積み上がった関係や信頼もほとんどない。

ただ、今のやり方が Market Memory 全体のマーケティング戦略になってはいけない、という考えははっきりしてきた。

投稿数を増やすことが、必ずしもより多くの関心につながるわけではなかった。

自動生成される要約を継続して出すだけでは、  
人がアカウントを覚えたり、サービスに関心を持ったりする状態にはなりにくいのかもしれない。

これからは、単に投稿を積み重ねるだけでなく、  
関係のある人たちの会話に参加し、直接意見を交わすやり方も必要に見える。

そして来週は、Threads 以外のコミュニティにも少しずつ足を入れてみようと思っている。

Reddit や Hacker News のように、  
新しいプロジェクトを紹介してフィードバックをもらえる場所を見ている。

最初からあちこちにリンクをばらまくやり方は避けたい。

それぞれのコミュニティがどんな話をしている場所なのかを先に見て、  
Market Memory に合うテーマに参加しながら、自然にプロジェクトを紹介してみたい。

売り込むよりも、  
なぜこのサービスを作ったのか、  
どんな問題を解こうとしているのか、  
いま何を確かめたいのかを正直に話すほうが、  
今の段階には合っていると思う。

## ここまでの結果を受け止めながら

現時点までのマーケティングの成績はよくない。

時間をかけて投稿を作ったが、反応はほとんどなく、  
登録にもつながらなかった。

その事実を無理によく解釈する必要はない。

ただ、これが Market Memory 全体に価値がないという結論でもない。

いま確認できたのは、  
今の Threads 運用だけではユーザーを連れてこられなかったという事実だ。

プロダクトの問題かもしれないし、メッセージの問題かもしれない。

チャネルの問題かもしれないし、  
まだ誰も知らないアカウントに対して、結果を急ぎすぎた問題かもしれない。

いまはまだ、それらを切り分けて確認していく必要がある。

開発しているときは、できた機能が結果として残った。

でもプロダクトを外に出したあとは、  
何の反応もない時間も、ひとつの結果として受け止める必要があるように思う。

その無反応のなかでどこが詰まっているのかを探し、  
別のやり方でまた試すことも、プロダクトを作る過程の一部だろう。

いまは、もともと計画していたフェーズ2には進めずにいる。

代わりに、現実が新しいフェーズ2を見せている。

機能を増やす段階ではなく、  
人を探しに行き、話を聞き、  
Market Memory が本当に必要な理由を確かめる段階だ。

まだ答えはない。

ただ来週は、今のような投稿を繰り返すことから少し離れて、  
別の場所で人と直接会話を始めてみようと思う。

いまは、そのくらいの次の一歩で十分だ。
