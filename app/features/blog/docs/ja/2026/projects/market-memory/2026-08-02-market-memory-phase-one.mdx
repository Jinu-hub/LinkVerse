## 予想と違った結果

今回は、これまでより長く考えた。

サービスの構造からコンテンツ、画面、多言語対応まで、自分なりに丁寧に準備し、  
実際に使える形で Market Memory を公開した。  
開発だけで終わらせないために、SNSアカウントも作り、いろいろな形で投稿もしてみた。

だが、意味のあるユーザー流入は起きなかった。

予想していたよりも、はるかに静かな結果だった。  
サービスをつくるあいだにかけた時間と期待があったぶん、気持ちは重く、  
数日間は他のことに集中しにくいほど、その結果が気になっていた。

その過程で、ひとつはっきり分かったことがある。

良いサービスをつくろうと努力することと、人が実際に訪れ使ってくれることは、まったく別の問題だった。  
開発が上手いだけでは足りなかった。

## 計画を見直すことにした

最初は、Phase 1 を終えたあと Phase 2、Phase 3 と続けて機能を広げていく予定だった。

だが Phase 2 は、ひとりで機能を足していく段階ではない。  
実際のユーザーの反応を確認し、フィードバックを受けてサービスの方向を調整する段階だ。

ユーザーがいない状態で、自分が考えた機能を増やし続けることには、大きな意味はないと判断した。  
それはサービスを育てることというより、検証されていない仮説をひとりで広げていくことになりやすい。

だから、これまでの計画はここで止めることにした。

Market Memory の Phase 1 は、今の状態でひと区切りにする。

## 終了ではなく、最小限の運用

Market Memory を完全に止めるつもりはない。

今ある自動化とレポート生成の仕組みを使えば、大きな負担なくサービスを維持できる。  
新しい機能開発は当面止めるが、市場レポートとコアデータはこれからも積み上げていく予定だ。

時間が経てば、いま積み上がっていくデータが、再び開発を始めるための土台になるかもしれない。  
他のプロジェクトを進めるなかで得る経験や新しい視点を、Market Memory に活かす可能性もある。

だから今の選択は、失敗を宣言することでも、プロジェクトを捨てることでもない。

すぐに広げず、再び動く理由と方向が見えるまで、最小限の状態で保っておく選択に近い。

## 出発点を変えてみる

これまで私は、思いついたアイデアを先に具体化し、  
サービスをつくったあとで人に見せるやり方で動いてきた。

これからは、この順番を変えてみたい。

何をつくるかを先に決めるより、人が実際にどんな不便を抱えているかをまず見ていきたい。  
繰り返し現れる問題は何か、  
人が何かを解決するために時間と費用を使っている場面はどこか。それを観察したうえで、そのなかからアイデアを育てていきたい。

もちろん、これが正解かどうかはまだ分からない。

ただ今回の経験を通して、自分がつくりたいものだけを見ているやり方には、はっきりした限界があると学んだ。  
次は、つくることより観察することを、少し前に置いて始めてみようと思う。

Market Memory は、しばらく速度を落とす。

そして私は、他の勉強とプロジェクトを続けながら、人が抱える問題をあらためて見る練習を始める予定だ。
